1. 项目概述

1.1 项目背景

数据分析是近几年求职热度最高的方向之一，但公开讨论里同时存在两种完全相反的说法：一种说“月薪两万起步、供不应求”，另一种说“卷到简历投不出去、学历卡死在本科”。

这两种说法都有出处，问题是它们描述的不是同一批岗位。作为大数据技术专业的专科在读生，我需要的不是一个笼统的判断，而是一组能直接指导投递动作的事实：哪些岗位我真的能投、这些岗位在哪些城市、门槛落在学历还是经验上、起薪的合理区间是多少。

这类问题靠听经验得不到答案，因为每个人的样本都只有自己那几十次投递。所以我决定用公开的招聘数据自己算一遍。

1.2 项目目标

项目围绕四个递进的决策问题展开，每个问题对应一张图表：

  1. 岗位结构 —— 数据分析类岗位到底分几种方向，各自的机会量和薪资水平如何？
  2. 城市选择 —— 机会集中在哪些城市，高薪城市是否等于好入门的城市？
  3. 门槛量化 —— 学历和经验这两个硬条件交叉之后，我的“可投范围”有多大？
  4. 薪资预期 —— 起薪的合理区间是多少，经验增长带来的涨幅出现在哪个阶段？

1.3 我的工作范围

从拿到原始表格到输出结论，全流程独立完成，包括：数据可信度核查、缺失值与异常值的判定规则设计、中文薪资文本解析、分析字段衍生、探索性分析、图表设计与绘制、结论提炼。

其中工作量最大也最关键的一步不是画图，而是定口径——同一份数据，用全量口径和控制变量口径算出的学历溢价差距接近 12 个百分点。这个差异如果不解释清楚，后面所有结论都站不住。

1.4 核心成果

  • 建成 3,984 条 × 25 字段的分析宽表，薪资可量化率 83.7%
  • 输出 4 张图表，每张对应一个求职决策问题
  • 沉淀 4 条可直接转化为投递动作的结论（见第 5 章）
  • 全流程留痕：4,002 条清洗审计明细、数据质量报告、可复现脚本

2. 数据源与采集方案

2.1 数据来源

本项目使用的是猎聘（liepin.com）职位列表页的第三方开源抓取快照，由开源分析项目整理后公开在 GitHub 上。

  • 抓取时间：2019-12-03 至 2019-12-20（连续 18 天）
  • 抓取关键词：数据分析
  • 覆盖范围：全国
  • 原始规模：4,002 条 × 15 字段

2.2 字段结构

原始 15 个字段可按用途分成六组：

分组 字段 说明
时间 发布日期 精确到日，用于分析发布节奏
岗位 岗位名称、工作年限、学历 岗位名称是后续派生“方向”和“职级”的唯一依据
薪酬 薪酬low、薪酬high、几薪 三个字段需联合解析才能还原月薪
地点 工作城市、城市2、城市3、地区 后三个字段缺失率极高（96%、98%、65%）
企业 公司名称、公司行业、其他方面 其他方面为福利标签串，34.5% 缺失
标识 链接 平台唯一键，用于去重

2.3 采集口径与合规边界

这一点必须在报告里写清楚，否则结论再漂亮也是空中楼阁：

  • 数据仅包含招聘平台公开可见的列表页字段，不涉及企业联系人、投递者简历等非公开信息
  • 公司名称在源数据中已做过部分脱敏处理
  • 这是第三方整理的公开抓取数据，不是猎聘官方发布，不能表述为“猎聘官方数据”
  • 用途限定为学习与分析实践，不做商业使用

把“第三方抓取”写成“官方数据”，在面试里属于诚信问题，不是措辞问题。这个边界我选择主动说明。

2.4 数据可信度验证

拿到一份来源不算权威的数据，第一步不是分析而是质疑。我用五个互相独立的内部特征来判断它是否来自真实抓取：

验证角度 观察结果 说明
周末效应 工作日日均 280 条，周末日均 16.5 条，相差 17 倍；每个周六日必然塌陷 招聘行为受作息驱动，合成数据不会模拟出这种周期
详情链接 4,001 条全部指向 liepin.com/job/*.shtml，其中 3,983 条唯一；岗位 ID 为 9–10 位且前缀集中在 1920–1925 符合 2019 年该平台的号段特征
薪资取值 73 个不同薪资值全部为整千，无小数 对应平台“15–25k”的整数展示格式
脏值形态 行业字段混入融资阶段 733 行、岗位名带统一前缀、城市字段填省份 33 行 真实页面解析的结构性残留，人工编造通常更“干净”
发布衰减 距抓取日越远条数越少（12-03 为 78 条，12-20 为 1,221 条） 符合“发布越早、越可能已下架”的快照特征

五条证据指向同一结论：数据大概率来自真实页面抓取，而非人工生成。但能自证不等于有官方背书，所以引用时仍然按“第三方抓取的公开数据”表述。

2.5 数据源选型的取舍

选数据时对比了几个选项，这里记录判断依据：

方案 规模 优势 放弃原因
阿里云天池 · 智联招聘人岗匹配赛题数据 478 万条 平台官方、有许可证可引用 单机处理成本高；对个人项目而言，“百万级筛选”的说服力不足以抵消一周的清洗时间
招聘平台现爬 — 数据最新 反爬机制（滑块、设备指纹）时间成本远超收益
本项目采用：开源抓取快照 4,002 条 量级适中、字段完整、可直接开工 年份偏旧、无 JD 全文

核心取舍逻辑：个人项目的价值不在数据多大，而在结论能不能站住。 4,000 条数据用 pandas 十分钟就能跑完，省下的时间可以用来做口径控制和交叉验证——这才是面试里真正被追问的部分。

3. 数据预处理与清洗

3.1 清洗总览

原始数据有六类问题，处理原则是：能定规则的定规则，不能定规则的留标记，绝不为了“好看”而丢弃信息。

问题类型 涉及范围 处理策略 是否留痕
重复记录 16 条完全重复 + 2 条链接重复 删除 是
缺失值 城市 600 条、几薪 646 条、地区 2,607 条 分字段处理，不统一填充 是
薪资文本 4,002 条全部为字符串 按 5 种格式规则解析为数值 是
异常值 统计异常 68 条、业务异常 5 条 分别保留与剔除 是
字段错位 行业混融资词 733 行、公司名异常 664 行 拆分字段、标记异常 是
类型错误 学历、经验、日期均为中文文本 转为有序类别 / 数值 / datetime 是

清洗后：4,002 → 3,984 行 × 25 列，其中薪资可量化 3,334 条（83.7%）。

3.2 去重

分两步，因为重复的性质不同：

  1. 完全重复：16 条，所有字段完全一致，直接删除
  2. 业务重复：同一 链接 出现多次（2 条），保留字段完整度最高的一条

平台唯一键去重比整行去重更可靠——同一条招聘被爬两次时，抓取时间不同会导致整行不完全相同，但链接一定相同。

3.3 缺失值：为什么不做统一填充

这是整个清洗里最需要判断力的一步。常见做法是“数值填均值、类别填众数”，但在这份数据上会直接导致结论错误。

关键案例：城市缺失 600 条（15.0%）。

我对比了缺失组和非缺失组的薪资分布，结果反直觉：

分组 条数 月薪中位数
城市缺失 487 ¥27,500
北京 516 ¥22,500
上海 766 ¥20,000

缺失组的薪资比任何一个真实城市都高。合理的解释是：高薪岗位（尤其是猎头代招、保密招聘）更倾向于不公开具体城市。

这意味着缺失机制是 MNAR（非随机缺失），而不是随机缺失。如果按均值填充，会把这 487 条高薪岗位拉低到平均水平；如果直接删除，会把高薪样本一起删掉，导致整体薪资被系统性低估。

最终处理：标记为“未知”并作为独立类别保留，在城市对比时单独排除，同时在第 4 章把这个现象本身作为一条发现来报告。

其余字段的处理：

字段 缺失数 处理方式 理由
几薪 646 (16.1%) 按 12 薪补全，并保留“是否填补”标记 12 薪为行业默认值，补齐后可计算年薪，标记便于回溯
城市2 / 城市3 3,853 / 3,927 与地区合并为“区域”字段 单字段无分析价值，合并后有区县维度
地区 2,607 (65.1%) 同上 缺失率过高，不单独出结论
其他方面（福利） 1,379 (34.5%) 仅统计标签数量，不计算标签占比 缺失率过高时，任何“福利覆盖率”都会被系统性低估
学历 / 工作年限 极少 标“未知” 量太小，不影响分组

3.4 类型转换：把文本变成可计算的东西

（1）薪资解析——最麻烦的一步。中文薪资有五种写法，需要分别处理：

原始写法 解析结果 说明
1.5-2.5万/月 15,000 – 25,000 元/月 标准月薪区间
0.8-1万/月 8,000 – 10,000 元/月 后半段继承“万”单位
6-9千/月 6,000 – 9,000 元/月 单位为千
20-30万/年 16,667 – 25,000 元/月 年转月，除以 12
200-300元/天 剔除 日薪无法与月薪直接比较
面议 剔除出薪资统计 645 条，16.2%

生成月薪下限、上限、中位数（上下限均值），再结合几薪计算年薪。

（2）学历转有序类别：中专/中技 < 大专 < 本科 < 硕士 < 博士，建立数值化的“学历层级”，才能做相关性分析。

（3）经验转数值：“1年以内”→1，“1-3年”→1，“3-5年”→3，“5年以上”→5，“经验不限”→单独标记为缺失而非 0。把“不限”当成 0 年经验会污染整条经验曲线。

（4）日期转时间类型：同时派生出“星期”，为第 4 章的发布节奏分析做准备。

3.5 异常值：三类判定，三种处理

异常值最忌讳一刀切删除，因为“异常”可能是真实存在的高薪岗位。

类型 判定规则 数量 处理 理由
统计异常 IQR 法（超出 Q1−1.5IQR 或 Q3+1.5IQR） 68 条（2.0%） 保留 薪资分布右偏（偏度 2.18），IQR 假设近似正态，照此剔除会误删真实的高薪专家岗
业务异常 月薪 < 1,000 元 / 几薪 > 24 / 薪资倒挂（下限 > 上限） 5 条 剔除出薪资统计 明显违反常识，属于录入错误
逻辑异常 公司名 = 行业词、城市字段填省份 664 + 33 行 标记，不删 影响企业维度分析，但不影响薪资与城市主结论

对统计异常“保留但标记”的结果是：报告里同时给出中位数（主口径）和 5% 截尾均值（对照口径），读者可以看到极端值的影响有多大，而不是让分析者替读者做决定。

3.6 字段衍生：从 15 列到 25 列

新增的 10 个字段是分析能力的基础：

派生字段 规则 用途
月薪下限 / 上限 / 中位 / 年薪 由薪酬三字段计算 所有薪资分析的基础
薪资口径 / 薪资分析可用 区分公开与面议，标记是否进入统计 控制全篇口径一致
岗位方向 按岗位名称关键词归为 6 类（数据分析 / 大数据分析 / 数据统计 / BI 报表 / 算法挖掘 / 数据开发数仓） 岗位结构分析
职级 从岗位名称提取助理/专员/高级/资深/专家/经理/总监 控制变量，区分“title 溢价”与“学历溢价”
学历层级 学历转有序数值 排序与相关性分析
经验档位 / 经验年限下限 中文经验转标准化档位 经验溢价分析
行业_清洗 / 融资阶段 从混入融资词的行业字段中拆出 企业维度分析
星期 由发布日期派生 发布节奏验证

其中 薪资分析可用 这一个布尔字段是全篇的关键：所有涉及薪资的图表和数字，都以它为过滤条件。这样四张图的分母一致，结论之间才能互相印证。

3.7 留痕与可复现

  • 输出 4,002 条审计明细，每条改动记录序号、字段、原值、新值、原因
  • 原始文件全程只读，清洗前后 md5 一致
  • 清洗脚本可重跑，结果确定

留痕不是形式主义。面试官问“这个 92% 的可用率怎么算的”，能当场翻出明细，比任何解释都有说服力。

3.8 两个差点被忽略的坑

坑一：行业字段有 421 行整格只有一个“轮”字。

原因很清楚——爬虫把“A轮”的字母截掉了。看起来只要把“轮”加进融资阶段词表就能解决，但这样会让“汽车轮胎”“轮胎制造”这类真实行业名被误判成融资阶段。最终用特例规则处理：整格等于“轮”时判为融资阶段，作为子串出现时不判。

坑二：城市字段混入 33 行省级值（广东、山东、江苏等）。

如果不处理，城市排名里会凭空出现“广东”这样的条目，读者会误以为广东是继北京上海之后的第三大市场，实际是把多个城市的岗位合并了。处理方式是标记异常，并在城市分组时过滤样本量小于 30 的组。

4. 探索性数据分析

4.1 描述统计：先确定用哪个指标

在比较任何两个分组之前，必须先确认用均值还是中位数。这份数据的答案是中位数：

指标 数值
样本量 3,334 条（薪资可量化）
均值 ¥21,798
中位数 ¥18,500
标准差 ¥14,774
P10 / P25 / P75 / P90 ¥7,000 / ¥11,500 / ¥30,000 / ¥40,000
最小值 / 最大值 ¥1,500 / ¥160,000
变异系数 CV 0.678
偏度 2.18
峰度 10.00

均值比中位数高 17.8%，偏度 2.18、峰度 10.0，说明分布是典型的右偏长尾：大部分岗位集中在中等区间，少数极高薪岗位把均值拉高。

如果报告用均值，等于让 1% 的高薪岗位代表所有人的预期薪资。所以后续所有分组比较一律使用中位数，均值只作为“行业总包”的参考。按年薪口径（含几薪），中位数为 ¥240,000/年。

4.2 图 1｜岗位方向：机会量与薪资梯度

图表要素 说明
图表类型 横向条形图（双面板）+ 误差棒
X 轴 左图：岗位数量（条）；右图：月薪中位数（元/月）
Y 轴 岗位方向，按样本量降序排列
样本范围 薪资可量化且样本量 ≥ 50 的方向

为什么这样设计：把“机会量”和“薪资”拆成两个面板，因为这两个维度经常背离——机会最多的方向不一定最赚钱，只看一张图容易得出片面结论。

读图结论：

  • 数据分析方向占全量 89.6%（2,990 条），是唯一具备规模的主入口，其余方向都是窄口
  • 方向之间的薪资差异其实不大：数据分析 ¥18,500、大数据分析 ¥21,250、BI/报表 ¥21,500、算法/挖掘 ¥22,500，最高与最低相差 21.6%
  • 真正的异常值是“数据统计”：75 条，月薪中位仅 ¥9,000，不到数据分析的一半

这条“数据统计”的低薪线有个现实意义：这类岗位在 JD 里同样写 SQL、Excel、报表，看起来是数据分析的“平替”，但薪资差了近一倍，且岗位量只占 2.1%，更接近运营统计或文员类工作。对求职者的直接启示是筛选岗位时要按 title 排除掉它。

口径说明：抓取关键词是“数据分析”，因此“数据开发/数仓”仅 6 条未进入图表。这不代表市场上该方向岗位少，而是采样偏差，必须在报告中说明，否则会被误读为“数据开发没有岗位”。

4.3 图 2｜城市：机会密度与薪资水平

图表要素 说明
图表类型 双 Y 轴组合图（柱状 + 折线）
X 轴 城市，按岗位数量降序，仅保留样本 ≥ 30 的城市
Y 轴 左轴：岗位数量（条）；右轴：月薪中位数（元/月）

为什么这样设计：城市选择本质是“机会多”和“给得多”的权衡，必须同屏对比。样本量门槛设 30 是为了避免样本太少的城市被平均值带偏（例如只有 2 条岗位的城市排到第一）。

读图结论：

  • 上海（766）、北京（516）、深圳（305）、广州（300）、杭州（231）五城合计 2,118 条，占薪资样本的 63.5%，机会高度集中
  • 薪资上北京最高（¥22,500），上海/深圳/杭州并列 ¥20,000，广州最低（¥12,500）
  • 二线城市中，成都 ¥15,000 明显高于武汉 ¥12,500、南京 ¥13,500、苏州 ¥11,250

一个容易被误读的点：广州薪资在一线城市里最低，看起来是“性价比差”。但结合图 3 的交叉分析会看到，广州恰恰是低门槛岗位最集中的城市——低薪对应的是更低的进入门槛，而不是同样的岗位给更少的钱。

4.4 图 3｜学历 × 经验：岗位机会矩阵

图表要素 说明
图表类型 带数值标注的热力图（交叉列联表）
X 轴 经验要求：不限 → 1 年以内 → 1-3 年 → 3-5 年 → 5 年以上
Y 轴 学历要求：中专/中技 → 大专 → 不限 → 本科 → 硕士
格内数值 该组合的岗位数量及其占全量的比例

为什么这样设计：投递被拒的本质是“自身条件和岗位要求不匹配”，而学历和经验是最硬的两个筛选条件。把两者交叉，可以直接看到“自己所在的格子”有多大，比单独看学历分布有用得多。

读图结论：

  • 最大的一格是 本科 + 1-3 年：1,636 条，占全量 41.1%。市场的主力需求根本不在“无经验的在校生”这一格，这解释了为什么数据分析岗看起来遍地都是、投出去却很少有回音
  • 大专学历、且经验不限或 1 年以内：169 条，仅占 4.2%——这是专科学历求职者真正可投的池子
  • 大专 + 1-3 年也有 174 条，说明专科生并非只能投无经验岗位，有 1 年经验后选择面反而更宽

这张图最直接的价值是把“我该投多少岗位”从感觉变成数字：不是“海投几百家”，而是“精确锁定 169 条，逐条定制”。

4.5 图 4｜经验阶梯：起薪分布与档位涨幅

图表要素 说明
图表类型 箱线图（箱体为 P25–P75，横线为中位数）
X 轴 经验要求，按门槛由低到高；“不限”单独用灰色箱体区分
Y 轴 月薪（元/月）

为什么这样设计：均值会被极端值拉高，箱线图能同时展示中位数、四分位区间和离群点，读者可以看到“同样的经验要求，薪资的离散程度有多大”。

读图结论：

经验要求 样本量 P25 中位数 P75
1 年以内 462 ¥7,000 ¥10,000 ¥15,000
1-3 年 1,676 ¥12,500 ¥18,000 ¥26,500

  • 涨幅曲线是前陡后缓：1 年以内 → 1-3 年涨 80%，1-3 年 → 3-5 年涨 67%，3-5 年 → 5 年以上只涨 33%
  • 最有价值的发现是最后一行：写“经验不限”的岗位，中位数只有 ¥9,000，比写“1 年以内”的还低 10%

“经验不限”通常被理解为“门槛低、好进”，但数据显示它更像是低薪岗位的信号——真正愿意培养新人的公司会明确写“1 年以内”，而写“不限”的岗位往往职责杂、定位模糊，薪资也上不去。

4.6 交叉分析：学历溢价到底有多少

单看分组结果会说“大专 ¥9,000、本科 ¥20,000，差了 55%”，但这个数字是混合口径，把学历差异和岗位结构差异混在了一起。所以做了三层控制：

分析口径 大专中位 本科中位 差距 说明
全量 ¥9,000 (n=366) ¥20,000 (n=2,601) −55.0% 混合了学历与岗位结构
固定岗位方向（数据分析） ¥9,000 (n=327) ¥20,000 (n=2,348) −55.0% 几乎无变化，因为该方向本身就占 89.6%
固定方向 + 固定职级（均无职级标注） ¥10,000 (n=198) ¥17,500 (n=1,438) −42.9% 差距收窄 12.1 个百分点

怎么解读这个结果：

差距从 −55.0% 收窄到 −42.9%，收窄幅度占总差距的 22%。这意味着岗位结构效应只能解释一小部分，学历门槛是真实存在的。

如果反过来表述成“学历差距全是岗位结构造成的，能力够就行”，就与数据不符了。这类“控制变量后结论缩水但仍显著”的表述，比任何一边倒的结论都更可信，也更经得起追问。

同口径下还有一个反直觉现象：硕士的月薪中位数（¥20,000）与本科完全相同，“不限学历”组反而最高（¥22,500，但混入了专家岗）。这说明数据分析岗的学历溢价主要卡在“大专 → 本科”这一档，读研的边际收益在这个岗位上并不明显。

4.7 两个计划外的发现

发现一：缺失值不是随机丢的。

如 3.3 节所述，城市缺失的 487 条岗位薪资中位 ¥27,500，高于北京。这不是数据质量问题，而是一条业务信息——高薪岗位更倾向于隐藏所在地。把它当作“脏数据”删掉，就等于把最有价值的那批样本删掉了。

发现二：招聘启事上的薪资区间，宽度中位数是 62.5%。

计算每条岗位“上限/下限−1”，中位数为 62.5%（P25 为 42.9%，P75 为 94.4%）。也就是说，一条写着“15–25k”的岗位，上限比下限高出六成是常态。

这条对求职者的意义是：谈薪时应该用区间下限做锚点，而不是中值。如果拿“15–25k”的中间值 20k 去谈，实际很可能落在 15–18k 区间。

5. 业务结论与项目价值

5.1 四条面向求职的结论

结论一：筛选岗位时，“数据统计”要避开，它不是数据分析的平替

数据：数据分析 2,990 条，中位 ¥18,500；数据统计 75 条，中位 ¥9,000，低 51%。

这两类岗位的 JD 里都写 SQL 和 Excel，技能要求看起来差不多，但薪资差近一倍，岗位量只占 2.1%，更接近运营统计或文员类工作。

可执行动作：简历标题统一写“数据分析”，投递时直接排除含“统计员”“数据专员”“数据运营”字样的岗位。同样的技能，在正确的 title 下溢价接近一倍。

结论二：学历不占优时，广州、深圳的实际机会比北京更多

数据：TOP5 城市占 63.5%，北京中位最高（¥22,500）、广州最低（¥12,500）。但“大专 + 应届可投”的 169 条里，广州 36 条 > 上海 30 条 > 北京 14 条。

北京的高薪对应更高的学历与经验门槛，对无经验的专科生反而最不友好；广州薪资低，但低门槛岗位密度最高。

可执行动作：学历是短板时，优先在广州、深圳投递，用可投岗位密度换面试机会；把北京留给积累了 1-3 年经验之后的跳槽阶段。

结论三：不要海投“本科起”的岗位，把筛选条件锁定在 169 条上

数据：全量中本科岗位 3,123 条（78.4%），大专岗位 387 条（9.7%）。但大专岗位中 43.7% 对无经验开放，本科岗位只有 20.4%。

这个对比是反直觉的：低门槛岗位确实更愿意带新人，开放比例是本科的两倍多，问题只是总量少。所以正确策略不是去投本科岗碰运气——简历筛选阶段就会被过滤——而是把条件固定为“学历要求 = 大专 且 经验要求 ∈ {不限, 1 年以内}”，在 169 条里做深度定制。

可执行动作：逐条改写简历关键词，针对每个岗位写定制化的项目说明。在 169 条上做到 30% 的定制率，效果远好于在 4,000 条上做到 0%。

结论四：第一份工作的目标不是起薪，是尽快拿到“1-3 年经验”这个标签

数据：1 年以内 ¥10,000 → 1-3 年 ¥18,000（+80%）→ 3-5 年 ¥30,000（+67%）→ 5 年以上 ¥40,000（+33%）。

从 0 到 3 年累计涨幅 200%，远大于 3 到 5 年的 33%。前三年是薪资增长最快、也最不该纠结起薪的阶段。同时要注意：写“经验不限”的岗位（355 条）中位仅 ¥9,000，比“1 年以内”还低 10%。

可执行动作：优先投明确写“1 年以内”的岗位；入职后主动争取能写进简历的完整项目（从取数到结论的闭环），这才是三年后跳槽的定价依据。

5.2 项目价值

对个人求职：这套分析直接回答了我自己的三个问题——投哪类岗位、去哪座城市、期望薪资怎么报。结论已经转化为具体的投递策略，不是做完就归档的课程作业。

方法论上的可复用性：

  • 口径控制：三类学历对比证明“控制变量后结论会变但不会消失”，这套方法可以套用到任何“分组差异”的分析场景
  • 缺失机制判断：先对比缺失组与完整组的分布，再决定填充还是保留，而不是默认使用均值填充
  • 留痕与可复现：审计明细 + 只读原始文件 + 可重跑脚本，构成一个能被质疑、也能自证的最小闭环

对同类求职者：这份数据里关于“专科 + 应届”的结论（169 条可投池、43.7% 的开放率、广州的密度优势）是可以直接复用的，尤其对大数据、统计、信息管理类专业的专科生。

6. 项目总结、局限性与后续优化

6.1 项目总结

这个项目从 4,002 条带脏值的原始表格出发，最终产出 3,984 条 × 25 字段的分析宽表和 4 条可执行的求职结论。过程中真正花时间的不是画图，而是三件事：判断数据能不能信（第 2.4 节的五项验证）、决定缺失值怎么处理（第 3.3 节的 MNAR 判断）、确认结论的口径边界（第 4.6 节的三层控制）。

收获最大的一点是：数据分析的说服力来自“我知道我的结论在什么条件下不成立”，而不是“我的结论很漂亮”。 比如主动说明抓取关键词单一导致“数据开发”只有 6 条、学历差距控制变量后只收窄 22%、薪资绝对值因数据年份而过时——这些“减分项”写在报告里，反而让剩下的结论更可信。

6.2 局限性

  1. 数据年份偏旧（2019 年 12 月）。薪资绝对值已不代表当前行情，本报告的所有结论都限定在“结构”与“相对差异”层面，未引用任何绝对薪资作为当下预期。
  2. 抓取关键词单一（仅“数据分析”）。因此“数据开发/数仓”只有 6 条、“BI/报表”只有 69 条，这是采样偏差，不代表市场上这些方向的真实占比。
  3. 缺少 JD 全文。无法做技能维度分析（SQL / Python / Hive / Tableau 的提及率、技能组合溢价），这是本项目最大的能力缺口。
  4. 城市缺失 487 条且非随机。虽已单独处理，但城市维度的结论仍然只覆盖公开了城市的岗位。
  5. 薪资为 JD 声称区间的中点。代表招聘方的挂牌价，不等于实际 offer；645 条“面议”岗位因信息缺失被整体排除，可能引入样本选择偏差。

6.3 后续优化方向

  1. 补爬 500 条岗位详情页，抽取技能关键词，做“技能组合 × 薪资”分析，回答“会 Hive 比只会 SQL 多拿多少”这类问题。
  2. 接入更近期的数据集重跑同一套 pipeline，验证经验溢价结构（+80% / +67% / +33%）是否依然成立，这是判断结论时效性的唯一办法。
  3. 把清洗与绘图封装成可配置脚本，只改关键词和城市参数就能复用到其他岗位方向（如“数据开发”“算法工程师”）。
  4. 引入简单的统计检验（Mann-Whitney U 检验），验证“大专 vs 本科”的差异是否显著，而不只是比较中位数高低。
